# Changelog

This changelog follows the [Keep a Changelog](https://keepachangelog.com/pt-BR/1.1.0/) format. The project uses semantic versioning and remains at `0.x` until the contract (JSON plan, `meister.config.yaml`, and log events) stabilizes. The `#N` numbers are pull requests.

## [Unreleased]

### Added
- **`meister report` measures the complexity of the changed functions.** After each subtask is integrated, the Python functions it created or edited are measured (1 + `if`/`elif`, loops, `except`, each extra `and`/`or` operand, comprehension `if`, `match` cases) and a `complexity_check` event is logged. Four new rows ("Functions changed (Python)", "Functions above complexity 10", "Functions with higher complexity", "Highest complexity") and a `complexity` block in the JSON; a run without the event shows `not measured`. It only measures: it never blocks the gate, and a measurement failure never affects the run. The number is stricter than `ruff` C901, which ignores `and`/`or` and comprehension conditions.
- **`meister report` counts the gate repairs.** Two new rows, "Gate repairs" and "Tasks with a gate repair" (also `gate_repairs` and `gate_repair_tasks` in the JSON `attempts`), read from the `gate_repair` events already in the log; a run without repairs shows `0`. They let you compare runs, for example before and after `workers.targeted_tests`.
- **`workers.targeted_tests` (enabled by default): workers run only the tests of the files they changed.** Every worker prompt now asks it to leave the whole test suite and the repository-wide linters and type checkers to the evidence gate, which runs them in full afterwards and sends failures back. In 311 measured Claude worker sessions, 51% ran the whole suite at least once (479 full runs), each taking minutes and re-read on every later turn. Set `false` to restore the old prompt. The cost effect is not measured yet.
- **The `/timeline` page lets you choose which project to see.** A **Project** box in the top bar (the same registry as `/config`) loads that project's runs and timeline from its own log, with the prices, lanes and silence threshold of its own `meister.config.yaml`. The choice goes in the URL (`/timeline?project=<id>`); `/api/runs`, `/api/timeline` and `/api/timelines` accept `?project=<id>` (404 `unknown_project`, 409 `project_missing`). Read-only: nothing is written in the other project.
- **Editing `/config` over Tailscale for authorized logins.** `dashboard.remote_edit_logins` (default: empty) lists the Tailscale logins (header `Tailscale-User-Login`, case-insensitive) that may save the configuration through remote access; everyone else stays read-only. The other write guards still apply.
- **A "Save to all projects" button on `/config`.** It writes the lane list being edited into the current project and every other registered project (`POST /api/config/replicate`), skipping projects with a run in progress or a missing folder, keeping a `.bak` of each existing file and reporting the result per project. A failure in one project does not stop the others.
- **The `/config` screen shows which project it is configuring and lets you switch.** A **Project** bar shows a select box and the full path; the lanes, the source file and the active-run block all follow the chosen project. Projects come from a registry in `~/.meister/projects.json` that fills itself (`meister config web`, starting a dashboard, `meister orchestrate`), plus **Discover projects** (scan a folder up to 3 levels) and **Add project** (one absolute path; needs `.meister/`, `meister.config.yaml` or `.git`). The routes accept the project id and only registered ids are valid. Configuration stays per project.
- **The `/config` lane drawer lists the known models of the lane's harness.** The model field gets a tree with each model's id, cost when known and source: `agy models` (read live), the Codex cache (`~/.codex/models_cache.json`), the Claude aliases and ids, and the Copilot cache. Free text still works, and a model missing from the lists shows an "unknown model" notice without blocking the save. Each harness spells the same model differently (`claude-haiku-5.5` on Copilot, `haiku` or `claude-haiku-5-5` on the Claude CLI), so the id comes from the tree. The lists are served read-only at `GET /api/config/models?harness=...`.
- **`meister config refresh-models copilot` reads the Copilot model list from its own `/model` selector.** Copilot has no list command, so the command opens the interactive selector once in a simulated terminal (no prompt is sent, so no credit is spent), parses the real screen, and updates `~/.meister/model_catalog/copilot.json`, keeping the previous file as `.bak` and leaving it untouched if no model could be read. It is opt-in and never runs by itself.

### Fixed
- **The idle timeout no longer cuts a worker that is waiting on a test run.** A test runner or linter (`pytest`, `mypy`, `ruff`, `vitest`, `jest`, `tsc`, `eslint`, `cargo test`, `npm test`, `mvn test`, `go test`) running inside the worker's process now counts as activity, including when started through its script (`python3 .../bin/pytest`). Long-lived processes that are not runners (for example MCP servers) never count, and `workers.max_runtime_seconds` still applies. Before, a worker waiting on a 2 to 5 minute suite produced no change in the pane or in `git status` and was declared idle (42 idle timeouts in the log).
- **A worker uses the same `meister.config.yaml` the orchestrator loaded, even when the file is not in git.** Workers run in a worktree (a checkout of the last commit), so an untracked or uncommitted configuration was invisible to them and they fell back to the packaged default catalog: a lane defined only in the project (for example `tier_2b`) failed with "Unknown lane", and lane timeouts and `eligible_classes` were ignored. The loaded configuration now records the absolute path of its file and the worker task carries it.
- **A harness failure shows the cause when its output has a quota signal.** The worker error used to say only "failed with exit code 3"; when the harness output contains a signal recognised by the quota detector, the message now appends that excerpt (up to 200 characters).

## [0.12.0] - 2026-10-18

### Added
- **`gate.flaky_retries` also covers vitest.** Before rejecting a vitest failure, the gate reruns only the failing test files with the project's local vitest (up to `gate.flaky_retries` times); if they pass, the full gate runs once more and decides, and the tests are reported as `flaky_tests`. A pytest failure still takes priority, and without a local `node_modules/.bin/vitest` nothing is rerun. No new option.
- **A run started without `--name` gets a readable name from its plan file.** When the first task's title is a generic `Task N: ...`, `meister orchestrate --plan-file checkout-sem-conta.json` names the run "Checkout sem conta" (a leading `YYYY-MM-DD-` is dropped). `--name` still wins.
- **The timeline marks tasks reused by a resumed run.** A task reused from an earlier run (`subtask_reused`) is drawn as a fixed-width dashed marker with a "Reused" legend entry, instead of a zero-width bar stacked at the start of the axis; the tooltip still names the source run and the original duration.

- **The `/config` screen shows the lane chain and edits every field of a lane.** Lanes appear in levels with the lateral fallback (`tier_1` → `tier_1b` → `tier_1c`) and the escalation to the next level, with the cost jump between levels. A simulator shows where a task of a given class would run when chosen lanes fail. A content card (harness, model, effort, cost) can be dragged, or tapped, from one slot to another to swap content while the slot keeps its name and policy. A drawer edits every field of a lane, and lanes can be created, renamed and removed (a new level goes at the end of the chain). Saving still keeps the comments of `meister.config.yaml`. The design is in `docs/superpowers/specs/2026-10-17-config-cadeia-de-vias-design.md`.

- **`meister config web` opens the `/config` screen directly.** It finds or starts the project's dashboard, opens the page in a window or tab (`--no-open` only prints the URL) and does not reuse a dashboard started by an older version of the code: it starts a new one and says so. The dashboard state now records the code version, and the `/config` page shows a notice instead of "undefined" when the server is older than the page.

### Fixed
- **The timeline reason for a vitest failure no longer starts with the stack-frame marker (`❯ `).** The gate-failure summary lists a vitest test once, from the `FAIL file > suite > test` lines (the progress lines with timings are ignored), so `js_failed_tests` has no duplicates and no durations.
- **The timeline tooltip shows the execution under the mouse.** A task that ran on several lanes (for example `tier_1`, `tier_1b`, then `tier_2`) is drawn once per lane, but every bar listed the attempts of all lanes and the final status. Each bar now lists only the attempts of its lane, with their original numbers, the outcome of that lane and its own total and wait times.
- **Reused tasks no longer inflate "Peak parallel" and "Average parallel".** After a `--resume`, the eight tasks reused in a fraction of a second counted as eight simultaneous workers (peak 8); they are now left out of both numbers and still count as completed.

### Other changes
- **The Codex lane (`tier_1c`, Luna) is enabled in the default catalog.** It sits between `tier_1b` (Luna on Copilot) and `tier_2` (Gemini), so when Copilot runs out of credits the fallback tries Codex before Gemini. The default catalog, `meister.config.example.yaml` and the file written by `meister config init` agree. Codex credits are limited: a project that wants the old behaviour sets `enabled: false` on the lane. A `meister.config.yaml` that lists `workers.tier_order` replaces the whole list, so existing projects keep their own setting.

## [0.11.0] - 2026-10-16

### Added
- **Monorepos with Node subpackages pass the gate without configuration.** After installing the root, the gate also installs every subdirectory (up to 3 levels deep) that has its own `package.json` and lockfile, skipping `node_modules`, `.git`, `.venv`, `dist` and similar, and skipping all of it when the root declares `workspaces` or `pnpm-workspace.yaml`.
- **`gate.install` accepts a list of commands** (`["npm ci", "npm --prefix backend ci"]`), run in order and stopping at the first failure. The string form still works. Commands run without a shell, so `&&` inside a single string never worked; use the list.
- **The gate failure message says when a dependency is missing** (`Cannot find package`, `Cannot find module`, `Failed to resolve import`, `No module named`), with the names and a hint to set `gate.install`, so the operator does not read it as a rejected test.
- **`meister worker --timeout`** (seconds, default 180) replaces the fixed Herdr wait; the timeout message now says partial work is archived under `refs/meister/archive/*`.
- **A gate repair now sees which vitest test failed.** The failure summary recognises vitest output (`FAIL file > suite > test`, the assertion line and the `Test Files`/`Tests` counts) instead of passing the last lines of a DOM dump. The names go into a new `js_failed_tests` field, kept apart from `failed_tests` so the pytest rerun and the scope check are unchanged, and into the `gate_repair` and `subtask_rejected` events.
- **The timeline shows why the gate rejected an attempt.** The tooltip used to print only `Deterministic gate failed in worker worktree:` for vitest failures; it now shows the failing test, or the test file and line taken from the failure summary, and keeps the old text when nothing is recognisable.

### Fixed
- **`plan import` no longer drops files silently from `**Files:**`.** Several backtick-quoted paths on one line all count, text after the path (`(append at the end)`) is ignored, `Rewrite` works as `Modify` and `Delete` is accepted. A line with a known verb and no backtick path now prints a warning instead of vanishing.
- **The integration worktree setup event carries the right run.** `worktree_setup_ok` and `worktree_setup_failed` for the integration worktree were logged with the previous run's id, which stretched run durations in reports (a 3-minute run showed as 70) and credited the `setup` phase to the wrong run.

## [0.10.0] - 2026-10-13

### Changed (incompatible)
- **`meister dashboard --host` outside loopback requires `--allow-remote`.** The dashboard has no authentication, and before this any address was accepted silently. Without the flag the command now exits with an error; with it, it prints a warning and starts. Loopback (`127.0.0.1`, `::1`, `localhost`) is unchanged. Anyone who exposes the dashboard on the network must add `--allow-remote`.
- **Minimum Python is 3.10.** The declared floor was 3.9, which was never tested; `requires-python`, `meister setup` and the CI matrix now all use 3.10, the version CI and mypy already assumed.
- **Lanes have neutral names.** Names that embedded a model or harness are replaced; update `workers.tier_order`, `meister.config.yaml`, `--model` arguments and any script that uses them. The old names no longer exist in the default configuration.

  | Old name | New name |
  |---|---|
  | `copilot_luna` | `tier_1b` |
  | `codex_luna` | `tier_1c` |
  | `agy_gemini_flash` | `tier_2` |
  | `claude_sonnet` | `tier_3` |

  The new `tier_1` lane (GitHub Copilot CLI with Claude Haiku 5.5) is the first choice by default. Model, harness and price stay in configuration (`meister/default_config.yaml` and `meister.config.yaml`), not in the lane name.

### Added
- **`plan validate` and `plan analyze` warn about existing tests that cite the task's files.** When a test already in the repository names symbols from a file in a task's `**Files:**`, the plan gets a warning, so you can add that test to `**Files:**` if the task changes its behavior on purpose.
- **`meister gate`** runs the deterministic verification gate for a project (`--path`), with exit code 0 when it passes, 1 when it fails and 2 on an infrastructure error. The managed pre-commit hook runs it, so the hook and the gate use the same commands.
- **README GIFs no longer suggest the tool is hard to use.** The live timeline (nothing typed) is now the opening image, and the terminal recordings moved to an "Under the hood" section, one command each, saying that the orchestrator LLM runs them and the user does not type them. The 60-second start spells out that a plain-language request is the whole interface.
- **README rewritten to make the case for MeisterRouter, with new GIFs.** A new opening, a "what you stop doing" table, a 60-second start, three real terminal recordings (a plan running in parallel, the gate rejecting and repairing a task, the quota fallback) and a sharper live-timeline GIF, in English and Portuguese. Herdr moved out of the main text into its own optional section. The recording kit is in `docs/img/src/` (`record.sh`; the workers are simulated, so it spends no quota).
- **The timeline demo has localized, neutral names.** `python -m meister.timeline_demo` takes the run name and the 12 task titles from the language catalogs (English or Portuguese) instead of fixed Portuguese text.
- **`meister config init --kiro`.** Generates a `meister.config.yaml` that uses only the Kiro CLI (`router.mode: first`, lanes `tier_1`, `tier_1b` and `tier_2` on `kiro-cli`, no network or OpenRouter key). `docs/kiro.md` now points to it.
- **Guide and example for testing Java batch jobs without a staging environment.** `docs/java-testing-without-staging.md` and `docs/examples/java-batch-testing/` (Java 8, Maven, WireMock, JUnit 5; 14 tests, no Docker): fixtures with recorded JSON, fake site with failure scenarios, golden master, dry-run and a read-only check of the real site.
- **Timeline: the two gates and the integration queue are labeled.** The web timeline labels a task's two gates (`gate: worktree da tarefa` and `gate: após integrar a base`), calls the wait before integrating `fila de integração` (integration queue), also in the legend, and no longer draws integrate slices shorter than 2 s between phases. See [docs/advanced.md](docs/advanced.md#web-timeline).
- **Kiro CLI as a harness (`kiro-cli`, alias `kiro`):** workers run `kiro-cli chat --no-interactive --trust-all-tools`, with optional `--model` and `--effort`; a configuration with only Kiro lanes and `router.mode: first` needs no Copilot, Claude, Codex or OpenRouter. The quota fallback does not trigger for Kiro and its credits do not appear in the usage reports. See [docs/kiro.md](docs/kiro.md).
- **Java/Maven in the gate:** `gate.env` (default empty) sets environment variables for the gate commands, and with `JAVA_HOME` its `bin` goes first on the `PATH`; a `pom.xml` is detected without `gate.commands` and runs `mvn -B -q test`, resolving Maven from the project's `mvnw`/`mvnw.cmd`, `mvn` on the `PATH`, then `MAVEN_HOME`/`M2_HOME`; `target/**` is tolerated by default in `scope.tolerated_files`. See [docs/java-maven.md](docs/java-maven.md).
- **`retry.worker_error_attempts` (default `1`; `0` turns it off).** When a worker returns an error (for example, the harness exits with code 1 on a transient failure), Meister logs a `worker_retry` event (`reason: worker_error`) and retries on the same lane; once those retries are used up, it falls back to the next lane in `workers.tier_order`. The run fails only when no lane is left. Before this, a single worker error failed the whole run despite `max_retries` and other lanes. With `0`, the old behavior is kept. See [docs/advanced.md](docs/advanced.md#advanced-configuration).
- **`runtime.host` selects where workers run.** It chooses the adapter that hosts each worker: `herdr`, `tmux` or `process`. See [docs/advanced.md](docs/advanced.md).
- **`process` adapter:** workers run as background processes, with no terminal multiplexer, so MeisterRouter works without Herdr installed.
- **`tmux` adapter:** workers run in tmux panes, as an alternative to Herdr.
- **`meister logs`** shows the output of a worker, which matters most with the `process` adapter, where there is no pane to look at.
- **`MEISTER_WORKER` environment variable** marks a process as a MeisterRouter worker, whatever the host. `MEISTER_IN_PANE` is kept and still honored.
- **Native Windows support (under validation):** new `meister.osops` layer that holds the OS-specific code (POSIX in `posix.py`, Windows in `windows.py`), `psutil` as a dependency only on Windows, a fix for `os.kill(pid, 0)`, and hooks written with LF line endings. Linux and macOS behavior is unchanged.
- **Unstable-test detection in the gate (`gate.flaky_retries`, default `2`; `0` turns it off).** When the gate fails on pytest tests, it first reruns only those tests in the same worktree (up to `flaky_retries` times). If they pass, the full gate runs once more and is the final authority: if it passes, the task is approved with the `gate_flaky` event listing the tests, and no repair worker is opened. If a test keeps failing, or the failure has no test ids (lint, collection), the rejection and the repair flow stay as before. Unstable tests no longer cost a model session and several minutes of repair.
- **`meister wait [--run-id ID] [--timeout S] [--format text|json]`** blocks until a run ends and exits with a code that says how: `0` completed, `1` failed, `130` interrupted, `124` timeout, `2` usage error. It only reads the log (never writes), follows resumed runs and lets an orchestrator agent be notified without polling. See [docs/advanced.md](docs/advanced.md).
- **The timeline describes the run by itself:** `meister orchestrate --name TEXT` records a readable run name (`run_name` in `orchestration_start`; without it, a name derived from the plan) shown in the web timeline header, selector and page title; each attempt is drawn on the lane where it ran, with lateral fallback told apart from escalation; the lane header comes from the run's `worker_spawn` events (`harness`, `model`, `effort`); and the task tooltip lists the attempts with lane, outcome and `detail` (files outside the scope, failing gate line, quota line). Only fields were added; older logs keep the previous display. See [docs/advanced.md](docs/advanced.md#web-timeline).
- **Timeline demonstration:** `python -m meister.timeline_demo` serves the web timeline over a synthetic log, in `static` or `live` mode (`--speed` for live), with no model and no cost. See [docs/advanced.md](docs/advanced.md).
- **Page on the data sent to Jev:** [docs/jev-data-sent.md](docs/jev-data-sent.md) lists, field by field, what `classify` and `control` send to OpenRouter and what never leaves the machine (workers run through the local harnesses). The contract is locked by `tests/test_jev_payload_contract.py`: changing a field requires updating the page.
- **Web timeline (`/timeline`) readability:** time axis in minutes, right-angle dependency arrows, tooltips with phase, task and wait durations, lane header with `harness · model (effort)`, and a completion/failure sound with a button and the `s` key (off by default, preference saved per browser).
- **`effort` per lane:** an optional reasoning level passed to the harness (values depend on the harness: `copilot` and `github-copilot` accept none, minimal, low, medium, high, xhigh, max). When omitted, the harness argv is unchanged from before.
- **`workers.enabled`:** turns lanes on or off in the configuration, written safely, without ever leaving the configuration with no lane enabled.
- **`meister models --enable` / `--disable`:** turns a lane on or off from the command line; the `models` table shows a column with each lane's effort.
- **`/config` screen in the dashboard:** shows the effective lanes and edits on/off, order, harness, model, effort and `max_parallel`, validated like `meister config validate`; it writes `meister.config.yaml` with `ruamel.yaml` (comments kept), a `.bak` and an atomic swap, offers **Restore default**, and is read-only while a run is active or for remote access. A **Config** link sits in the timeline header. `ruamel.yaml` is a new runtime dependency. See [docs/advanced.md](docs/advanced.md#the-config-screen-lanes).
- **`scope.allow_dependency_files` (default `false`):** when `true`, a task may also edit the files declared by the tasks it depends on, directly or transitively, which are already integrated before it starts. Files of unrelated tasks stay blocked, and `meister.config.yaml` is never meant to be edited by a worker. With `false`, scope is unchanged. See [docs/advanced.md](docs/advanced.md#advanced-configuration).
- **Claude Haiku 5.5 on lane `tier_1`** (GitHub Copilot CLI harness) as the default first lane.
- **`meister plan new [--tasks N] [--format markdown|json] [-o FILE] [--project]`** writes a plan skeleton ready to fill in: Markdown by default (title, `## Global Constraints`, N `### Task K:` blocks with `**Files:**` and `**Depends on:**`), or the canonical JSON array with `--format json`. Without editing, it passes `meister plan import` and `meister plan validate`. `--project` fills the Global Constraints with rules read from the project's `CLAUDE.md` and `AGENTS.md`, when they exist, and never invents any. See [docs/plan-format.md](docs/plan-format.md#meister-plan-new).
- **`meister plan guide [--lang en|pt-BR]`** prints the plan format rules for the model writing the plan: the flow, many small tasks, `**Files:**` as the scope checked by the gate, `**Depends on:**` only for real dependencies, what not to do, and examples in Markdown and JSON. The `init` templates now start the plan flow with `plan guide` and `plan new`. See [docs/plan-format.md](docs/plan-format.md#meister-plan-guide).
- **`meister plan import --format auto|markdown`:** the default is now `auto`, which detects a Markdown task plan or a canonical JSON plan; `markdown` is the name of the native format.

### Fixed
- **A test outside scope that fails the gate ends the task as `scope_conflict` without spending a repair.** The work is archived in `refs/meister/archive/*`, and the task is not sent to a repair worker that cannot edit that test.
- **A harness killed by a signal is an infrastructure failure, not a reason to escalate.** A harness process that ends by signal (for example SIGKILL or SIGSEGV) is reported as an infrastructure error and does not move the task to a larger model.
- **The gate's rejection message starts with the failing tests.** The first lines name the tests that failed, before the rest of the output.
- **Meister's own commits no longer run Git hooks.** Internal worker and integration commits use `--no-verify`, because the gate already verified them before the commit; a project's pre-commit hook does not reject them.
- **A git commit failure after a passing gate is an infrastructure error.** It is reported with git's output instead of as a gate failure.
- **An unexpected exception closes the subtask as `FAILED`.** It no longer leaves the subtask in progress.
- **Archiving ignores `.venv`.** The archive of loose work no longer includes the project's virtual environment.
- **README links to "How to use" and "Herdr" opened nowhere.** The headings carried an invisible emoji selector (U+FE0F) that GitHub keeps in the anchor. The headings now use emojis without it, and the docs link test matches GitHub's anchors.
- **A gate infrastructure error now closes the subtask as failed.** The run summary used to show the task as `running` and `0 failed` after errors such as "No tests or linters detected" or a missing Maven; it now shows `FAILED`. The error message also lost its doubled period.
- **A project with no detectable tests no longer wastes a repair.** When the gate finds no tests or linters and `gate.allow_unverified` is off, it is now a gate infrastructure error: the run stops with a message to the project owner, the worker's work is kept, and the worker is no longer told to edit the protected `meister.config.yaml`. The gate-repair and gate-infrastructure console lines now follow `language: pt-BR`.
- **Resuming a run now continues the attempt numbering instead of restarting at 1.** `_execute_subtask_core` started every call with `attempt_count = 0`, so a task resumed under the same `run_id` reused attempt numbers (events, per-attempt files such as `<run>_<task>_<N>_task.json`, `.json` and `.exit`) and mixed old and new attempts in the timeline and reports. It now starts from the attempts already stored for the subtask (`subtasks.attempts`). Verified with a real interrupt and `--resume`: `worker_spawn` attempts 1 and 2.
- **The bridge now notices within a second when a worker's `run-task` process dies without writing a result.** The command typed into the worker pane is wrapped in `/bin/sh -c` so the shell records the exit code in a `.exit` file even if Python crashes or fails to import; the bridge then fails the attempt (event `worker_process_exited`, retry with `reason=process_exit` and the exit code, then failure without lane escalation) instead of waiting for the 600 s idle timeout. Measured with a real `kill -9`: detection in 0.6 to 0.7 s. The progress line now says "worker process exited with code N" and "gate repair" instead of the misleading "pane lost; retry".
- **Interrupting `meister orchestrate` no longer leaves the run "running" forever.** Ctrl+C, `SIGTERM` or `SIGHUP` now record an `orchestration_end` event (`status: interrupted`, exit code 130), mark the run `FAILED` (resumable with `meister orchestrate --resume`), keep the worktrees and branches, print which run was interrupted and exit with code 130. Before this, the run stayed `RUNNING` in the state database and the timeline kept drawing it as running.
- **A harness that exits immediately no longer hides its real error on macOS.** `HarnessWorker.run` called `os.getpgid` right after launching the harness; on macOS that raises `ProcessLookupError` when the harness has already exited, so the task failed with `[Errno 3] No such process` instead of the harness's own message and exit code. The process group is now the PID (the harness is a session leader) and recording the PID file never aborts the task.
- `test_start_server_port_0_allocates_port_and_cleans_up` no longer fails on slow runners: longer wait and a reset of the idle watchdog clock that earlier tests could leave stale.
- **Integration no longer discards loose work.** `rollback_merge`, reuse of an integration worktree (registered or not) and the `branch -D` retry in `create_worktree` now archive loose changes and unmerged branch commits (`refs/meister/archive/*`) before any destructive git command (`reset --hard`, `clean -fd`, `branch -D`, `rmtree`). If archiving fails the step does not run; a blocked rollback now fails the subtask with an `integration` error instead of being reported as a gate failure. Covered by `tests/test_worktree_integration_data_loss.py`.
- **`current_run.json` is written atomically**, so an interruption no longer leaves a truncated file that loses the run correlation.
- Cleanup failures are no longer silent: they log a `warning`, emit a `cleanup_failure` event and appear as "Cleanup failures" in `meister report`.
- Web timeline: an attempt still open when a worker is respawned now ends at the new spawn, instead of stretching to the end of the run.
- A worker that fails at startup on a configuration error (e.g. `Unknown lane`) now writes the error result and logs `worker_task_error` immediately, instead of waiting for the 600 s idle timeout and escalating to another lane.
- The Jev now receives opaque lane keys (`lane_a`, `lane_b`...) instead of lane names: names like `tier_N` made it read a ranking and pick a more expensive lane. Its answer is translated back to the real lane name, so `recommended_implementer`, `fallback_chain` and the telemetry keep the real names.

- **A `.venv` or `venv` symlink no longer counts as a change or enters a commit.** Change detection and commits ignore the project's virtual environment when it is a symbolic link.
- **The gate's tree calculation works with `.venv` ignored.** The tree hash used by the gate cache no longer fails when `.venv` is git-ignored.
- **`worker_timeout` carries `output_tail`, and `meister logs` shows the worker output with Herdr.** The event includes the last lines of the worker's output; with Herdr, that output is written to a log file only when a timeout happens.

### Other changes
- **README shorter: one "Get started" section.** "In 60 seconds", "Install" and "How to use" became a single section (two commands and one sentence for your LLM, with the live timeline opening by itself); the details moved to `docs/getting-started.md`. "Under the hood" now follows "Choose the models and their order".
- The engine (`bridge`, `workers`, `dag`, `events`) moved from `meister/herdr/` to `meister/engine/`; `meister/herdr/` keeps only what is Herdr-specific. The old paths `meister.herdr.bridge|workers|dag|events` remain as compatibility aliases (same module objects), so existing imports and patches keep working.
