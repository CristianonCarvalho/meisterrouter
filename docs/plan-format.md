# Plan format

MeisterRouter runs a **plan**: a list of tasks, each with the files it can change and
(optionally) the tasks it depends on. In direct use, you do not write or convert the plan by hand: your
orchestrator LLM (for example, Claude Code) generates, imports, and runs it following the rules that
`meister setup --project` installs (`CLAUDE.md`, hooks, and guard). This page explains the format so you
can review a plan or write one from scratch.

## Superpowers: recommended, not required

The format is the one generated by the **`writing-plans`** skill in the
[Superpowers](https://github.com/obra/superpowers) plugin for Claude Code. That is why Superpowers is the
recommended path: it guides the conversation (idea, design, plan) and delivers the plan in the right format.

```text
/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace
```

MeisterRouter works the same way without Superpowers: the plan only needs to use this format (any
LLM, or you, can write it) or the canonical JSON described at the end of the page.

## The plan in Markdown

```markdown
# Date search filter

## Global Constraints

- Python 3.10, no new dependencies.

### Task 1: Filter function

**Files:**
- Create: `src/filtro.py`
- Test: `tests/test_filtro.py`

Implement `filtrar_por_data(itens, inicio, fim)`. Write the test first.

### Task 2: Connect the filter to the screen

**Files:**
- Modify: `src/tela.py:40-80`

**Depends on:** Task 1

Call `filtrar_por_data` when clicking "Search".

### Task 3: Document

**Files:**
- Modify: `docs/*.md`

Update the documentation.
```

| Element | Rule |
|---|---|
| `### Task N: title` | One task per heading, numbered. Becomes the `task_N` id. |
| `**Files:**` | List the files the task can touch, one per line: `- Create: \`path\``, `- Modify: \`path\``, or `- Test: \`path\``. Line suffixes (`src/tela.py:40-80`, ignored) and globs (`drizzle/*`, `docs/*.md`) are accepted. The **scope gate fails** any change outside this list. |
| `**Depends on:**` | Optional: `Task 1` or `Task 2, Task 5`. The task only starts after the specified tasks. |
| `## Global Constraints` | Optional: project rules. Meister **summarizes** them for each task (it does not repeat the entire plan). |
| Task body | What the worker should do, with acceptance criteria. The more specific, the better the result. |

### Dependencies and parallelism

By default (`--deps sequential`), each task depends on the previous one: this is safest, but serial. With
`--deps files`, tasks depend on each other only when they share files or when you specify
`**Depends on:**`; independent tasks run **in parallel**, each in its own worktree. In the example above,
Task 3 only waits for Task 2 in sequential mode; in `files` mode, it runs alongside the others.
Tasks without `**Files:**` are only included with `--allow-unscoped` and run in isolation, without parallelism.

### Tips for a good plan

- **Small tasks**, each with a testable result (one code file and its test).
- **Declare all files**, including generated ones (lockfiles, `drizzle/*`), or add them to
  `scope.tolerated_files`.
- **Avoid overlap**: two tasks that modify the same file become sequential.
- Commands that generate files (`npm install`, `prisma generate`) cause the importer to warn if the generated
  file is not covered by `Files:` or the tolerated files.

## The canonical JSON

`meister plan import` converts Markdown to JSON; `orchestrate` accepts that JSON directly. Each
task has `id`, `description` (the text the worker receives), `target_files`, and `depends_on`:

```json
[
  {
    "id": "task_1",
    "description": "Task 1: Função de filtro\n\n...",
    "target_files": ["src/filtro.py", "tests/test_filtro.py"],
    "depends_on": []
  },
  {
    "id": "task_2",
    "description": "Task 2: Ligar o filtro à tela\n\n...",
    "target_files": ["src/tela.py"],
    "depends_on": ["task_1"]
  }
]
```

## Commands (for those who want to run them by hand)

```bash
meister plan import plano.md -o plano.json            # Markdown -> JSON (shows the task table)
meister plan import plano.md --deps files -o plano.json
meister plan validate plano.json                      # checks schema, dependencies, and forbidden keys
meister plan analyze plano.json                       # predicted parallelism and serial-plan warnings
meister orchestrate --plan-file plano.json            # runs it
```
More options (`--resume`, `--quiet`, `--allow-unscoped`) are in
[Alternative installation and advanced commands](advanced.md).
